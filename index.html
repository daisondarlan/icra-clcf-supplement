The Cross-Layer Consistency Framework: Catching Compounding Silent Failures in Safety-Critical Robot Perception

Safety critical robot perception pipelines are normally validated one layer at a time. Each stage passes its own local test, but nothing checks whether the stages still agree with each other once one of them changes. This work introduces the Cross-Layer Consistency Framework (CLCF), a set of six checks that test cross-layer agreement after a change. Applied end to end to a real depth-camera UAV landing-site classifier, the system fails five of the six checks. A unit-conversion bug in a tilt feature, whose fix is verified correct in isolation, silently invalidates the safety backstop's decision table. Rebuilding that table does not resolve the issue, because the backstop shares the classifier's own generalization ceiling.

02The CLCF Framework

Six checks for cross-layer consistency in safety-critical perception

Each check targets one way two pipeline stages can silently drift apart. C1 and C2 are evaluation-time checks. C3 and C4 are data-time checks. C5 and C6 are maintenance-time checks, run whenever any upstream stage changes.

C1

Split Independence

Training and test samples must come from different recording sessions. Adjacent frames from one recording are near duplicates and leak information across the split.

FAILED
C2

Full Rotation

Every session must serve as the held-out test set at least once. A single split gives no indication of how a model behaves on a genuinely new scenario.

FAILED
C3

Physical Plausibility

Labeled features must fall within physically plausible ranges derived from domain constraints, independent of the data. Violations above a set tolerance flag a data defect.

FAILED
C4

Synthetic Ground Truth

Each stage producing a numeric estimate must be verified against synthetic inputs with known ground truth, never only against another stage's downstream score.

FAILED
C5

Dependency Staleness

When a stage changes, every downstream artifact fit on its output must be rebuilt or re-validated before being trusted again. A verified fix can silently break a dependent model.

FAILED
C6

Backstop Generalization

The safety backstop must generalize at least as well as the model it protects, evaluated under the same held-out protocol. A backstop fit on the same data inherits the model's blind spots.

FAILED
03Field Test

Real outdoor flight over rubble and clean ground

A 105-second recording of real outdoor flight, sampled at 1 fps, shows the pipeline distinguishing a safe concrete patch from surrounding rubble. This flight predates the tilt-feature fix and the likelihood-table rebuild.

FIELD TEST

The flight demonstrates the full pipeline running on a real aircraft, not only on logged rows or in simulation. The clean concrete patch is repeatedly called SAFE with obstacle_ratio between 0.09 and 0.17, while the surrounding rubble is called NOT SAFE. This recording provides qualitative context and is not part of the formal quantitative benchmark.

04Dataset

UAV landing-site perception logs, eight sessions, 3,458 labeled rows

The dataset spans two collection phases. Phase 1 comes from real outdoor flights on a small multirotor UAV. Phase 2 was collected afterward in a controlled setup built to isolate two hazard types. The released tabular dataset underlying the quantitative analyses is provided here.

UAV landing-site perception dataset
Depth frames, extracted geometric features (tilt, flatness_std, obstacle_ratio), ground-truth labels (SAFE / NOT SAFE), and session metadata for all eight recording sessions. Includes both the pre-fix and post-fix tilt features and the likelihood tables used by the deployed classifier.
